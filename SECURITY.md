# Security Policy / Безопасность

## Сообщить об уязвимости

Пожалуйста, **не открывайте публичный issue** для уязвимостей.
Используйте приватный отчёт GitHub: вкладка **Security → Report a vulnerability**
в этом репозитории. Опишите, что нашли, как воспроизвести и чем это грозит.
Мы постараемся ответить в течение 7 дней.

Please report vulnerabilities privately via **GitHub → Security → Report a vulnerability**.
Do not open public issues for security problems.

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| `main` | ✅ |
| остальное | ❌ |

## Что считается проблемой безопасности

- Возможность поставить живой ордер в обход предохранителя (`OosStats::is_blocking()`),
  `CONFIRM_LIVE` или режима dry-run.
- Утечка приватного ключа, токена Telegram или других секретов в логи, журнал, отчёты.
- Удалённое управление (Telegram-бот, MCP, dashboard), которое позволяет больше, чем
  «читать состояние и остановить входы».

## Правила для пользователей

- Секреты — **только** в переменных окружения или в `.env` (он в `.gitignore`). Шаблон — `.env.example`.
- Для Hyperliquid используйте отдельный **API-кошелёк** (agent key), а не главный ключ.
- Перед коммитом: `gitleaks detect --source . --config .gitleaks.toml`.
- Если ключ попал в git — считайте его скомпрометированным: **сразу смените** его,
  а не только удаляйте из истории.
