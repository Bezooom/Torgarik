# 0008. Остановка файлом, Telegram только читает и стопит

**Status:** Accepted

## Context

Нужен способ остановить новые входы, не находясь за компьютером. Очевидное
решение – RPC/сокет с командами. Оно добавляет слушающий порт, аутентификацию,
сериализацию и новый класс уязвимостей в самый чувствительный момент: когда
что-то пошло не так и нужна остановка.

## Decision

- Остановка – **файл** `runtime/stop.flag`. Есть файл → новые входы блокируются,
  закрытия и брекеты работают. Shell перечитывает его каждый цикл и журналирует
  переходы.
- Telegram-бот – тонкий адаптер: `/status`, `/block`, `/stop`, `/resume`, `/help`.
  Он умеет читать состояние и трогать флаг. Ордеров не ставит никогда.
- Единственный разрешённый чат задаётся `TELEGRAM_CHAT_ID`; остальные
  игнорируются с предупреждением.

## Consequences

- Поверхность атаки – право записи в `runtime/`, а не сетевой сервис.
- Компрометация токена стоит простоя, не денег.
- Задержка остановки – до одного `loop_interval_secs`.
- Обратная сторона: на машине без `runtime/` остановить нечем; это принимается,
  потому что там нечего и запускать.

## Verification

- `set_read_clear_roundtrip`, `empty_file_has_no_reason_but_still_stops`
- `stop_and_resume_write_and_remove_the_flag`
- `read_only_commands_never_touch_the_flag`
- Smoke: `stop_flag set` → `signal blocked by kill-switch` → `stop_flag cleared`
