# Статистика против самообмана

**Инвариант.** Сырой Sharpe победителя grid-search не является доказательством
edge. Пока отчёт не несёт `deflated_sharpe_min` и `pbo_avg`, вопрос «доверять ли
результату» не имеет ответа, а kill-switch вынужден верить числу, которое
завышено по построению.

Код: `crates/backtester/src/stats.rs`. Пороги и гейты: `crates/common/src/config.rs`
(`OosSettings`). Формулы: Bailey & López de Prado (2012, 2014).

## 1. Почему сырой Sharpe врёт

Мы перебираем `N` конфигураций и берём лучшую по PnL. Даже если все `N` стратегий
– чистый шум, максимум их Sharpe будет заметно выше нуля: это максимум выборки, а
не свойство рынка.

| Величина | Что это |
|---|---|
| `N` (`n_trials`) | сколько конфигураций реально перебрали в фолде |
| `Var(SR)` | разброс Sharpe между испытаниями (не дисперсия доходностей) |
| `SR0` | какой Sharpe лучший из `N` даёт по удаче |
| `DSR` | вероятность, что настоящий Sharpe выше `SR0` |

## 2. Формулы, как они реализованы

Ожидаемый максимум:

$$SR_0 = \sqrt{Var(SR)}\left[(1-\gamma)\,\Phi^{-1}\!\left(1-\tfrac{1}{N}\right) + \gamma\,\Phi^{-1}\!\left(1-\tfrac{1}{N e}\right)\right]$$

где $\gamma \approx 0.5772$ – постоянная Эйлера-Маскерони, $\Phi^{-1}$ – обратная
функция стандартного нормального распределения.

Вероятностный Sharpe (PSR):

$$PSR = \Phi\!\left(\frac{(SR - SR^*) \sqrt{n-1}}{\sqrt{1 - \gamma_3 SR + \tfrac{\gamma_4 - 1}{4} SR^2}}\right)$$

где $n$ – число наблюдений, $\gamma_3$ – асимметрия, $\gamma_4$ – эксцесс
(**не** превышение: у нормального 3.0), $SR^*$ – порог сравнения.

Deflated Sharpe – это PSR с $SR^* = SR_0$:

$$DSR = PSR(SR_0)$$

`N = 1` даёт $SR_0 = 0$, то есть DSR сводится к обычному PSR. Это проверено тестом
`deflated_sharpe_punishes_more_trials`.

## 3. PBO через CSCV

Probability of Backtest Overfitting отвечает на другой вопрос: выживает ли
in-sample победитель out-of-sample.

Алгоритм в коде (`cscv_pbo`):

1. Матрица `T x N`: строки – наблюдения, столбцы – испытания.
2. Строки режутся на `S` последовательных блоков (`S = 10`, чётное, `>= 4`).
3. Для каждой комбинации половины блоков: IS = эта половина, OOS = остальные.
4. Победитель по Sharpe на IS; его ранг среди OOS-Sharpe даёт $\omega$.
5. PBO = доля разбиений, где $\omega \le 0.5$.

`None` возвращается, если данных мало: лучше «не знаю», чем ложная уверенность.

## 4. Откуда берутся данные

| Что | Как |
|---|---|
| `bar_returns` | доходность equity по каждому бару, `#[serde(skip)]` – в отчёт не пишется |
| `trial_sharpes` | Sharpe каждого испытания на окне отбора |
| матрица | те же испытания, выровненные по длине (обрезается до минимума) |

Считается в `walk_forward::scan_trials` один раз на фолд. Отчёт несёт только
агрегаты, поэтому `wf_latest.json` остаётся компактным.

## 5. Как читать числа

| Значение | Вердикт |
|---|---|
| `DSR <= 0` | победитель неотличим от удачи → live блокируется |
| `DSR` в (0, 0.95) | слабое свидетельство, нужен больший `n` или меньше испытаний |
| `DSR >= 0.95` | результат переживает поправку на `N` |
| `PBO <= 0.5` | in-sample победитель чаще выживает, чем нет |
| `PBO > 0.5` | отбор подогнан → live блокируется |

Гейты живут в `OosStats::is_blocking_with_settings`: `deflated_sharpe_floor = 0.0`,
`max_pbo = 0.5`. `max_pbo = 1.0` отключает проверку.

## 6. Ограничения, которые надо знать

1. `Var(SR)` считается по испытаниям **внутри** одного прогона. Если вы гоняли
   разные гипотезы руками, эта дисперсия их не видит – для этого есть
   [PREREG.md](PREREG.md).
2. CSCV требует одинаковой длины рядов; испытания с пропущенными барами
   выравниваются по минимуму, что слегка занижает `T`.
3. Дневные и часовые доходности дают разные `n` и разные пороги. Сравнивать DSR
   между разными таймфреймами нельзя.
4. DSR – вероятность, а не гарантия. Она отвечает «насколько это похоже на удачу»,
   а не «сколько я заработаю».

## 7. Проверки

```bash
cargo test -p backtester --lib stats
cargo run -p backtester -- --walk-forward --alpha trend --preset ethsol --report /tmp/wf.json
python3 -c "import json;d=json.load(open('/tmp/wf.json'));print(d['n_trials'],d['deflated_sharpe_min'],d['pbo_avg'])"
```

Ожидаемо: `n_trials` совпадает с размером сетки (7 для funding, 9 для trend),
`deflated_sharpe_min` и `pbo_avg` присутствуют в каждом новом отчёте.
