# Безопасность: секреты, поверхность управления, модель угроз

**Инвариант.** Ни один компонент, кроме `dyn Exchange` в live-режиме, не может
инициировать сделку. Удалённое управление умеет только читать состояние и
останавливать входы.

## 1. Секреты

| Секрет | Где живёт | Правило |
|---|---|---|
| `WALLET_PRIVATE_KEY` / `HL_API_PRIVATE_KEY` | только env | никогда в TOML, в git, в journal, в логах |
| `WALLET_ADDRESS` | env или `[exchange].wallet_address` | публичный, но обязан совпадать с ключом |
| `CONFIRM_LIVE=1` | env | явное подтверждение оператора |
| `TELEGRAM_BOT_TOKEN` | env | не в файле репозитория |
| `TELEGRAM_CHAT_ID` | env | единственный чат, которому разрешено управление |

`Settings::validate()` проверяет пару ключ/адрес и наличие подтверждения. Ошибка
валидации – отказ старта, а не предупреждение.

Что **не** является секретом и спокойно лежит в `config/*.toml`: лимиты риска,
сеть, символы, сетки параметров, пороги kill-switch.

## 2. Поверхность удалённого управления

| Компонент | Что может | Чего не может |
|---|---|---|
| `ml-trader --mode shell` | писать journal, ставить/закрывать по сигналам | работать без OOS-гейта и подтверждений |
| `ml-trader --mode tg-bot` | читать состояние, создавать/удалять `runtime/stop.flag` | ставить, отменять, менять размер |
| `mcp-server` | читать котировки, портфель, статус kill-switch | ставить ордера (нет такого инструмента) |
| `dashboard` | читать `runtime/` и отчёты | писать что-либо, кроме логов |
| `scripts/tg_notify.sh` | отправлять текст | управлять контуром |

`stop.flag` – файл, а не RPC: чтобы остановить входы, нужно уметь писать в
`runtime/`. Это сознательный компромисс: нет слушающего порта, нет токена, нет
сетевого кода в пути остановки.

## 3. Модель угроз

| Угроза | Что происходит | Смягчение |
|---|---|---|
| Утёк токен Telegram | чужой может нажать `/stop` или прочитать статус | ущерб = простой, не деньги; отзыв токена у `@BotFather` |
| Чужой чат пишет боту | игнорируется с предупреждением | сравнение `chat.id` с `TELEGRAM_CHAT_ID` |
| Утёк приватный ключ | полный контроль над счётом | ключ только в env, `CONFIRM_LIVE` обязателен, отдельный кошелёк под бота |
| Подменённый отчёт WF | можно «разморозить» live | pre-registration hash, свежесть, DSR/PBO в самом отчёте |
| Битый `wf_latest.json` | NaN мог бы выглядеть «зелёным» | fail-closed: non-finite метрики блокируют live |
| Подменённый `paper_state.json` | неверная книга, ложный PnL | валидация полей, карантин `*.json.bad`, журнал как источник истины |
| Компрометация машины | всё сразу | ключ с ограниченным балансом, `stop.flag` как быстрый тормоз, journal как аудит |

## 4. Что нельзя делать в этом репозитории

1. Класть ключи в `config/*.toml`, `.env` в git, скрипты или journal.
2. Добавлять MCP-инструмент, который ставит ордер. Текущий набор read-only – это
   свойство, а не недоделка.
3. Давать боту аргументы команд: `/stop now` понимается как `/stop`, всё
   остальное игнорируется. Расширять этот список нельзя без отдельного гейта.
4. Пускать LLM в путь ордера. Если LLM когда-нибудь появится, то только как
   источник мнения, не как исполнитель.

## 5. Проверка перед live

```bash
grep -rn "PRIVATE_KEY" config/ scripts/ docs/ | grep -v "env" # должно быть пусто
grep -rn "place_order" crates/mcp-server/src/                # должно быть пусто
cargo test -p ml-trader --lib tg_control
cargo test -p trading-common --lib      # включая fail-closed гейты
```

## 6. Логи и приватность

- journal не содержит ключей и адресов кошелька, только `coin`, `side`, `size`,
  причины блокировок;
- `WALLET_ADDRESS` попадает в конфиг и может попасть в лог – это публичные данные;
- Telegram-бот не пересылает journal целиком, только последние 5 событий и
  причины блокировки;
- данные L1 (наблюдение за кошельками) – публичная активность в сети, но она
  остаётся локальной и не отправляется третьим лицам.
